## 1. Навіщо

Власник має домашню батарею Marstek Venus E 3.0 (модель VNSE3-0, прошивка v151) і живе в Україні з частими відключеннями електромережі. Зараз станцію видно лише в офіційному додатку на iPhone, а:

- телефон не завжди під рукою, а ПК (живлений від станції) часто ввімкнений саме під час відключень;
- в офіційному додатку немає історії, яка власнику потрібна: **коли зникала і з'являлась мережа, скільки тривали відключення, статистика по них**;
- **помилки станції в офіційному додатку не показуються взагалі**.

Мета — десктопний додаток для Windows, який відповідає на питання «що зараз зі станцією, на скільки її вистачить, і як часто/довго не було світла», і зберігає цю історію. Власник користуватиметься ним сам і, ймовірно, викладе на GitHub для інших.

## 2. Цілі, не-цілі, анти-цілі

**Цілі продукту** (усі версії; що входить у першу — див. «Перша версія» нижче)
1. Поточний стан з одного погляду: заряд, потужність заряду/розряду, час до розряду / до повного заряду, час без світла сьогодні.
2. Облік відключень мережі: початок, кінець, тривалість; статистика за день / 7 / 30 днів / довільний період.
3. Журнал помилок і попереджень станції з поясненням людською мовою.
4. Сповіщення Windows: зникло/з'явилось світло, низький заряд, станцію заряджено, нова помилка, немає зв'язку.
5. Здоров'я батареї: фактична ємність, кількість циклів, температура.
6. Енергетика (другорядно): кВт·год заряду/розряду, мережа vs сонце, якщо є панелі.
7. Кілька станцій в одному додатку.
8. Три способи підключення: локальна мережа, хмара Marstek, Bluetooth (якщо є адаптер).

**Перша версія (v1) — тільки локальна мережа [вирішено]**
- Входить: підключення по LAN (UDP Open API), Огляд, Відключення, Помилки, Батарея, Енергія, трей, сповіщення, «Не турбувати», налаштування, uk/en, кілька станцій (усі — по LAN), локальна історія, інсталятор.
- **Не входить у v1:** хмара Marstek (наступна версія; рішення про неї — після v1, зокрема що робити, якщо вхід із додатка розлогінює телефон), Bluetooth (у власника немає адаптера), автоматичне завантаження і встановлення оновлень (у v1 лише повідомлення «є нова версія» з посиланням на GitHub Releases; SHA-256, SmartScreen-підказка і бекап БД з flows §6 — разом з автооновленням пізніше).
- Наслідки для v1: історія є лише за час, коли працював додаток; пропуски чесно позначені причиною «додаток не працював». Перший запуск: якщо станцію не знайдено, головна дія — інструкція «Як увімкнути локальний API» і «Вказати IP вручну» (кнопки входу в хмару немає). Плитки «Акаунт Marstek» у діалозі додавання станції немає (або вона неактивна з позначкою «незабаром» — на розсуд розробника). Злиття джерел (§7.2) у v1 вироджується в одне джерело, але інтерфейс `source` проєктується під кілька.

**Не-цілі**
- Керування станцією (зміна режимів, розкладів, лімітів) — тільки моніторинг. **[пропозиція]** — не обговорювалось явно; власник говорив лише про моніторинг.
- Версія для macOS — окремий майбутній проєкт; тут лише не заважати їй (див. §6).
- Публікація в Microsoft Store / App Store. **[вирішено]**
- Порівняння з графіками відключень ДТЕК/Yasno — відкладено на самий кінець, не в v1. **[вирішено]**
- Прогноз «чи встигне зарядитись до наступного відключення» — відключення непрогнозовані. **[вирішено]**
- Світла тема — пізніше. **[пропозиція]**

**Анти-цілі (провал, навіть якщо «працює»)**
- Додаток замальовує пропуски в даних або показує застарілі дані як поточні. Пропуски і вік даних мають бути видно чесно. **[вирішено]**
- Історія відключень неповна через те, що ПК був вимкнений, і додаток про це мовчить.
- Пароль від акаунта Marstek лежить відкритим текстом або дані користувача кудись відправляються, крім серверів Marstek.
- Додаток падає або «зависає» в некоректному стані, коли локальний API станції замовкає (відома проблема прошивок Venus E 3.0).

## 3. Обмеження і факти про середовище

- **Станція власника:** Venus E 3.0, ємність 5.12 кВт·год, макс. заряд 2500 Вт, макс. розряд 2 500 Вт (вихід без мережі, EPS; 800 Вт — лише ліміт віддачі в мережу) (значення беруться з профілю моделі, див. §7.6).
- **ПК власника** живиться від станції; вмикається час від часу; **Bluetooth на ПК немає** — BLE-адаптер неможливо перевірити на машині власника.
- **Роутер** живиться від станції; інтернет у провайдера працює добу+ без світла → поки станція жива, вона майже завжди онлайн у хмарі.
- **Локальний API Marstek (Open API):** JSON-RPC через UDP, порт 30000. Має бути ввімкнений на станції (через Marstek Venus Monitor по BLE або через підтримку Marstek). Методи за документацією/спільнотою: `Marstek.GetDevice` (виявлення), `ES.GetStatus`, `Bat.GetStatus`, `PV.GetStatus` та інші. Venus E 3.0 підтримується, але спільнота повідомляє про нестабільність на прошивках 138–148 (API замовкає через години, порожні відповіді). Для v151 даних немає.
  - Офіційна специфікація: <https://resource.marstekenergy.com/ems/resource/agreement/MarstekDeviceOpenApi.pdf>
  - Референсні реалізації: <https://github.com/jaapp/ha-marstek-local-api>, <https://github.com/taurgis/has-marstek-local-api>
- **Хмара Marstek:** публічного API немає; є реверс-інжиніринг з Android-додатка (<https://community.home-assistant.io/t/marstek-venus-e-first-version-of-a-cloud-integration/929840>, репозиторій DoctaShizzle/marstek_cloud). Може зламатись без попередження. Невідомо, яку історію (і чи журнал помилок) віддає хмара — **треба з'ясувати на першому кроці роботи з хмарою**.
- **Bluetooth:** неофіційний протокол, реверс-інжиніринг (<https://github.com/jaapp/ha-marstek-ble>, <https://rweijnen.github.io/marstek-venus-monitor>). Підтримка Venus E 3.0 не підтверджена.
- **Розповсюдження:** GitHub Releases, інсталятор без цифрового підпису (SmartScreen покаже попередження — пояснити в README). **[вирішено: GitHub; пропозиція: без підпису]**
- **Мови інтерфейсу:** українська і англійська, перемикання в налаштуваннях; за замовчуванням — мова Windows, якщо це uk, інакше en. **[пропозиція]**

## 4. Підходи (розглянуті)

| | Підхід | Плюси | Мінуси |
|---|---|---|---|
| **A** | **Go + Wails**, UI на HTML/TypeScript у WebView2 | Власник знає Go; макети вже в HTML; Go-ядро перевикористовується для macOS; малий інсталятор (~10–15 МБ) | Трей і сповіщення — у Wails v3, статус якого «alpha / API stable» (є тег v3.0.0, але документація ще пише alpha) |
| B | Rust + Tauri | Найзріліші трей, сповіщення, оновлення, інсталятор | Треба вчити Rust |
| C | C# + WinUI 3 | Найрідніший вигляд у Windows | macOS — з нуля; макети переписувати в XAML; нова мова |

Відкинуті одразу: Electron (важкий, без переваг перед A/B), Flutter (слабкі BLE і трей на Windows).

**Обрано: A (Go + Wails).** **[вирішено]** Причина: знайома мова, прямий перенос HTML-макетів, шлях до macOS без переписування логіки.

Розробник на старті фіксує версію Wails v3 (останній реліз/тег на момент старту) і перевіряє трей + сповіщення на Windows 11 у мінімальному прототипі. Якщо v3 непридатний — Wails v2 + окрема Go-бібліотека для трею і toast-сповіщень. **[на розсуд розробника]**

### 5.0 Рішення раунду hi-fi дизайну [вирішено]
Ці рішення мають пріоритет над описом нижче, де вони розходяться:
- Одиниці й формат: «год», «кВт·год» (не «г»); десяткова кома в uk («3,7»); англійська — «station», час 24 год en-GB.
- Кільце «Світло сьогодні» → **«Без світла сьогодні»**: у центрі реальний час без світла сьогодні **одним великим значенням, як у «Заряді»** — «5:27» з дрібним підписом «год : хв» під ним (менше години — «0:27»); під кільцем кількість відключень; заповнення (жовте) = частка дня, що минула, без світла; **жодних відсотків** на цьому кільці. Відсотки — лише в статистиці (вкладка Відключення).
- Кільця часу («До розряду», «До повного», «Вистачить на»): повне кільце = повна станція. «До розряду»/«Вистачить на» — заповнення = енергія понад поріг / повна корисна енергія; «До повного» — заповнення = поточний заряд.
- Права колонка: «Мережа» → «Світло».
- Графік заряду: червона пунктирна лінія порогу сповіщення про низький заряд.
- Журнал помилок: попередження з червоним контуром (жовтий зайнятий «без світла»).
- Налаштування → Сповіщення: лінійні іконки (не емодзі); кнопка «Надіслати тестове сповіщення»; перемикач «Станція, ймовірно, розрядилась».
- Трей: окрема іконка «дані застарілі» (STALE) і «підключення»; меню з підменю «Не турбувати» (1 год · 3 год · 8 год · До ранку · Доки не ввімкну); «Низький заряд» проходить завжди.
- Сповіщення 🪫 «Станція, ймовірно, розрядилась» — лише якщо виявлено наживо (див. flows §11 Q4).
- Видалення станції: за замовчуванням «Припинити стежити» (історія в архіві), видалення історії — окремою дією; 10-секундна смуга «Повернути».
- Назва станції у toast — у нижньому рядку («Дім · Venus E 3.0»): Windows не дозволяє дописати її до назви застосунку.
- Шрифт IBM Plex Sans / Plex Mono, вбудований у додаток (під час відключень інтернету може не бути).

### 5.1 Огляд [вирішено]
- **Верхній ряд — 4 кільця в однаковому стилі** (однакова товщина, сірий трек, заокруглені кінці, значення в центрі, підпис під кільцем):
  - **Розряд:** Заряд (%, «3.7 з 5.12 кВт·г») · Потужність (заповнення = |P| / макс. розряду, жовте, «420 Вт · розряд», «з 2 500 Вт макс.») · **До розряду** (год:хв, «до 10% · ≈ о 22:45») · Світло сьогодні (% часу доби зі світлом, «2 відкл. · 3 г 10 хв»).
  - **Заряд:** Заряд · Потужність (заповнення = P / макс. заряду, зелене, «з 2500 Вт макс.») · **До повного** (год:хв, «до 100% · ≈ о 16:10») · Світло сьогодні.
  - **Очікування** (P≈0) **[пропозиція, погоджено]:** Заряд · Потужність (0 Вт, «очікування», порожнє кільце) · **Вистачить на** (год:хв при середньому навантаженні під час минулих відключень) · Світло сьогодні.
- **Графік заряду станції (SOC, %)** з перемикачем 24 год / 7 днів / 30 днів: сірі смуги = мережі не було, над смугою підпис «без світла 2 г 00 хв»; пунктирна рамка + «немає даних» = пропуск у даних.
- **Права колонка:** Мережа (є / немає з ЧЧ:ХХ, тривалість) · Попереднє відключення · Помилки (нових немає / N нових) · Батарея (цикли, % ємності) · Джерело даних (LAN / хмара / BLE, вік даних «3 с тому»).

### 5.2 Відключення [вирішено]
- Перемикач періоду: Сьогодні · 7 днів · 30 днів · довільний діапазон (календар).
- Кільця: Світло за період (% часу), Покриття відключень (% відключень, які станція протягнула до кінця, «1 раз розрядилась раніше»). Статистика: кількість, середня, найдовша.
- **Стовпчиковий графік «Без світла по днях»** зі шкалою годин, сіткою і **тултіпом** на кожному стовпчику: дата, кількість відключень, сумарно без світла (+ % доби), найдовше (з часом), мінімальний заряд (червоним, якщо станція вимкнулась), «частково з хмари» якщо джерело змішане. Для періодів > 30 днів — стовпчики по тижнях. Клік по стовпчику фільтрує таблицю.
- **Таблиця подій:** початок · кінець (або «триває») · тривалість · заряд на початку → в кінці · примітка («станція розрядилась о 00:55», «частково з хмари»).

### 5.3 Помилки [вирішено]
Таблиця: коли · рівень (інфо / попередження / помилка) · що сталося (текст + код) · що робити (порада). Фільтр: усі / помилки / попередження / зв'язок. Сюди ж пишуться події зв'язку додатка (втрата LAN, перемикання на хмару).

### 5.4 Батарея [вирішено]
Кільця: Здоров'я (% фактичної ємності від номінальної), Ресурс циклів (N з ~6000), Температура (норма 0…45 °C). Графік ємності по місяцях з приміткою, що перші місяці оцінка приблизна.

### 5.5 Енергія [вирішено]
Той самий перемикач періоду, що у Відключеннях. Ліворуч підсумки: заряджено, віддано, ККД циклу. Згрупований стовпчиковий графік заряд/розряд (кВт·год) зі шкалою, легендою і тултіпами (заряд: з мережі / сонце; розряд: у т.ч. під час відключень; пік потужності). Кільце «Мережа / сонце» — тільки якщо є PV.

### 5.6 Кілька станцій [вирішено]
- Перемикач над вкладками → випадна панель з картками станцій: міні-кільце заряду, назва, модель, пігулки стану (світло є/немає з тривалістю, потужність або «очікування», джерело LAN/хмара з віком даних). «＋ Додати станцію», «Керувати станціями…».
- Вікно «Додати станцію»: три плитки — **Пошук у мережі** (рекомендовано), **Акаунт Marstek**, **IP вручну**; список знайдених станцій (модель, IP, прошивка, кнопка «Додати»); підказка, як увімкнути локальний API.
- Одна станція може мати кілька підключень одночасно (LAN + хмара + BLE) — див. §7.2.

### 5.7 Трей і сповіщення [вирішено]
- Іконка — батарейка з рівнем заряду і значком стану в правому нижньому куті: світло є (зелена), без світла (жовта + значок «вилка»), низький заряд (червона + «!»), заряджається (блискавка), немає зв'язку (сіра пунктирна + «×»). Має читатись на 16 px. Відображає **вибрану** станцію **[пропозиція]**.
- Тултіп іконки: «Дім · Venus E / 72% · розряд 420 Вт / Без світла 1 г 12 хв · вистачить на 7:30».
- Сповіщення: 🕯️ Зникло світло (час, заряд, на скільки вистачить) · 💡 Світло з'явилось (скільки не було, заряд, коли повна) · 🪫 Низький заряд (поріг, на скільки вистачить) · 🔋 Станцію заряджено · ⚠️ Помилка (текст + порада) · 📡 Немає зв'язку (ні LAN, ні хмари N хв). Назва станції — в рядку застосунку.
- Додаток стартує з Windows і при закритті вікна згортається в трей. **[вирішено]**

### 5.8 Налаштування [вирішено]
Окремий екран з меню розділів: Загальні (мова, автозапуск, згортати в трей, тема) · Сповіщення (перемикачі з описами по групах; поріг низького заряду 10/20/30/…%, за замовчуванням 20%; «немає зв'язку» після N хв, за замовчуванням вимкнено; тиха година, яка не глушить «Низький заряд») · Станції (назви, порядок, видалення) · Підключення (хмара: увійти/вийти, частота локального опитування, за замовчуванням 5 с) · Дані та історія (термін зберігання, за замовчуванням — завжди; експорт CSV) · Про програму (версія, перевірка оновлень на GitHub).

### 5.9 Тултіпи [вирішено]
Тултіпи ніколи не виходять за межі видимої області: позиціюються автоматично (зсув/перевертання до краю вікна).

## 6. Архітектура [пропозиція]

```
┌───────────── Wails app (Windows) ─────────────┐
│  frontend/  (TypeScript, HTML/CSS, графіки)    │
│      ▲ події стану, запити історії             │
│      │ (Wails bindings / events)               │
│  app/  — трей, сповіщення, вікна, автозапуск  │  ← залежить від ОС
├───────────────────────────────────────────────┤
│  core/ (чистий Go, без Wails і без ОС-API)     │  ← перевикористовується у macOS
│   source/local   UDP JSON-RPC :30000           │
│   source/cloud   хмара Marstek                 │
│   source/ble     Bluetooth (опційно)           │
│   merge/         злиття джерел у один стан     │
│   detect/        відключення, помилки, зв'язок │
│   forecast/      до розряду / до повного / вистачить на │
│   health/        ємність, цикли               │
│   store/         SQLite                        │
│   models/        профілі моделей станцій       │
└───────────────────────────────────────────────┘
```

- `core` — окремий Go-пакет (або модуль) без залежностей від Wails і Windows, щоб macOS-проєкт міг його імпортувати.
- Секрети (пароль/токен хмари) — через абстракцію `SecretStore`; на Windows — Windows Credential Manager.
- SQLite — драйвер без cgo (напр. `modernc.org/sqlite`), щоб збірка не вимагала C-компілятора. **[на розсуд розробника]**
- Бібліотека графіків у frontend — на розсуд розробника (вимоги: тултіпи з авто-позиціюванням, стовпчики/лінії/смуги-діапазони, темна тема).

## 7. Поведінка ядра

### 7.1 Модель даних [пропозиція]
- `stations` — id, назва, модель, серійник/MAC, підключення (LAN IP, cloud device id, BLE адреса), порядок.
- `samples` — часовий ряд: station_id, ts, soc %, power W (+ заряд / − розряд), grid_present (bool/невідомо), pv_power, battery_temp, джерело (lan/cloud/ble), сирий JSON (для діагностики, можна з обмеженням терміну).
- `outages` — station_id, start, end (null = триває), soc_start, soc_end, station_died_at (якщо розрядилась), джерела, позначка «частково з хмари / з пропуском».
- `gaps` — проміжки без даних з жодного джерела.
- `events` — помилки, попередження, події зв'язку: ts, рівень, код, текст, джерело.
- `daily_stats` — агрегати по днях для швидких графіків (можна обчислювати на льоту, якщо достатньо швидко).

### 7.2 Злиття джерел [пропозиція]
- Кожне підключення станції опитується незалежно. «Поточний стан» = найсвіжіші дані з усіх джерел; пріоритет при рівній свіжості: LAN > BLE > хмара.
- Кожне значення на екрані несе вік; якщо найсвіжіші дані старші за поріг (напр. 3× інтервалу опитування для LAN, 10 хв для хмари) — UI показує «дані застарілі, останні о ЧЧ:ХХ», а не «поточні» значення.
- Локальне опитування: інтервал за налаштуванням (5 с). При відсутності відповіді — експоненційний бекоф і повторне виявлення (UDP broadcast `Marstek.GetDevice`), бо IP може змінитись. Не вважати збій API збоєм станції: подія «втрачено LAN» → перемикання на інші джерела.
- Хмара: при старті додатка — дозавантаження історії за період, поки додаток не працював (наскільки дозволяє хмара); далі — опитування з помірним інтервалом. Точна поведінка залежить від того, що віддає хмара (див. §9).
- BLE: тільки якщо в системі є адаптер; інакше опція прихована/неактивна з поясненням.

### 7.3 Виявлення відключень мережі
- Відключення = проміжок, коли станція повідомляє відсутність мережевого входу. **Яке саме поле API це показує — з'ясувати** (кандидати: стан on-grid/off-grid, напруга/потужність мережевого входу в `ES.GetStatus`). Якщо прямого поля немає — запропонувати власнику евристику і погодити її до реалізації.
- Дебаунс: зміна стану фіксується, якщо тримається ≥ N секунд (напр. 30 с), щоб не рахувати мерехтіння. **[на розсуд розробника]**
- Якщо під час відключення станція розрядилась і зникла з усіх джерел — фіксується `station_died_at`; кінець відключення визначається за першими даними після повернення (станція з'явилась із мережею). Проміжок між ними — пропуск, позначений на графіках, а не «без світла» з вигаданою точністю.
- Відключення, частина яких відновлена з хмари, а частина з локальних даних, позначаються «частково з хмари».

### 7.4 Прогнози
- **До розряду:** (енергія понад нижній поріг, 10% за замовчуванням або значення з налаштувань станції, якщо API його віддає) / згладжена потужність розряду (ковзне середнє ~5 хв). Показувати також час «≈ о ЧЧ:ХХ».
- **До повного:** (енергія до 100%) / згладжена потужність заряду. Врахувати, що понад ~90% заряд сповільнюється (простий поправочний коефіцієнт або навчання на історії). **[на розсуд розробника]**
- **Вистачить на (очікування):** поточна енергія понад поріг / середня потужність розряду під час минулих відключень (за 30 днів; якщо історії ще немає — не показувати число, а «ще немає даних»).

### 7.5 Здоров'я батареї
- Цикли: з API, якщо станція віддає; інакше — сумарний розряд / номінальна ємність.
- Фактична ємність: оцінка з безперервних ділянок розряду з великою зміною SOC (напр. ≥ 50 п.п.): енергія / ΔSOC. Медіана по місяцю. У UI — примітка про точність.
  - Ділянка міряється від кроку SOC до кроку SOC (від першого зниження до першого досягнення найнижчого значення); простій до й після розряду не враховується. Один пропущений опит і відскок SOC на 1 п.п. ділянку не рвуть (план 2, Task 14).
  - Похибка вниз: потужність батареї — це баланс станції на боці змінного струму, а ΔSOC — дані BMS про комірки, тож втрати інвертора (кілька відсотків) занижують оцінку: нова батарея може показати трохи менше 100 %. Показ здоров'я обмежено 110 %, понад 105 % — з «≈» (шум оцінки).
- Цикли рахуються як еквіваленти паспортного циклу: віддана енергія / (RatedDoD × номінальна ємність); для моделі без цих даних — «—», не 0 (Ruling 19).
- Температура, прапорці BMS і енергія в батареї: **не показуються**. `ES.GetStatus` їх не віддає, а `Bat.GetStatus` додаток не викликає ніколи (рішення власника 2026-11-23, Ruling 57): на деяких прошивках він перезавантажує станцію, і на v151 власника після нього станція тричі замовкала й одного разу перезапустилась, що може знеструмити будинок (АВР). Ємність у прогнозах і в «X з Y кВт·год» — номінал моделі (`docs/dev-notes.md`).

### 7.6 Профілі моделей
Таблиця моделей: номінальна ємність, макс. заряд/розряд, мінімальний SOC за замовчуванням, ресурс циклів, діапазон температур, чи протестовано. Venus E 3.0 — «протестовано»; інші — «може працювати, не тестувалося». Нові профілі додаються через PR.

### 7.7 Помилки станції
Збирати коди помилок/попереджень зі всіх доступних джерел; таблиця «код → текст (uk/en) → порада». Невідомі коди показувати як «Невідома помилка (код X)», зберігати сирі дані. Звідки брати журнал помилок (LAN / хмара) — з'ясувати (див. §9).

## 7.8 Зберігання історії [рішення дизайнера, за підсумками рецензії]
- Сирі зразки (кожні ~5 с) — 30 днів; далі стискаються до похвилинних агрегатів (середнє/мін/макс SOC, потужності, температури; частка часу зі світлом) і зберігаються назавжди.
- Відключення, пропуски, події/помилки — назавжди, повністю.
- Сирий JSON відповідей станції — 7 днів (для діагностики).
- «Історія: зберігати завжди» в Налаштуваннях стосується агрегатів і подій. CSV-експорт: за останні 30 днів — посекундна деталізація, раніше — похвилинна.

## 7.9 Встановлення і ліцензія [рішення дизайнера, за підсумками рецензії]
- Інсталятор — **для поточного користувача**, без прав адміністратора (`%LOCALAPPDATA%`, автозапуск через `HKCU\…\Run`). Оновлення не просять прав.
- Брандмауер: інсталятор правило **не** додає. Якщо пошук станції не отримує відповідей і діагностика вказує на брандмауер (flows §1.5), додаток пояснює це і пропонує одноразову дію з підвищенням прав (UAC), яка додає правило для UDP 30000; або «Вказати IP вручну».
- Ліцензія проєкту — **MIT** (вже в репозиторії). Код для протоколів пишемо самі за описами (специфікація Marstek, нотатки спільноти). Код з GPL-проєктів не копіюємо; з MIT/Apache — можна, зі збереженням копірайту в `THIRD_PARTY_NOTICES`.

## 8. Конфіденційність і безпека [пропозиція]
- Дані користувача зберігаються тільки локально (`%APPDATA%`/`%LOCALAPPDATA%`); додаток нічого не відправляє нікуди, крім станції та серверів Marstek; немає телеметрії. (v1: додаток також звертається до GitHub — перевірка оновлень і завантаження оновлення, без персональних даних.)
- Пароль/токен хмари — у Windows Credential Manager.
- Перевірка оновлень — запит до GitHub Releases API, без персональних даних; можна вимкнути.

## 9. Відкриті питання для розробника (з'ясувати на старті)
1. Яке поле локального API Venus E 3.0 (v151) показує наявність мережі? Перевірити на станції власника.
2. Що саме віддає хмара Marstek: поточний стан, історія (з якою роздільністю і на яку глибину), журнал помилок?
3. Чи віддає локальний API коди помилок, кількість циклів, температуру?
4. Наскільки стабільний локальний API на v151 при опитуванні кожні 5 с упродовж доби (тест на станції власника)?
5. Статус Wails v3 (трей + сповіщення на Windows 11).

Відповіді на 1–3 можуть змінити те, які показники доступні; якщо щось недоступне ні з одного джерела, відповідний елемент UI ховається, а не показує вигадані значення.

## 10. Порядок робіт

## 11. Тестування [пропозиція]
- Симулятор станції (UDP-сервер, що відповідає як Venus E, з керованими сценаріями: відключення, розряд до нуля, мовчання API, порожні відповіді) — для автотестів ядра і ручної перевірки UI без реальної станції.
- Юніт-тести: виявлення відключень (дебаунс, пропуски, смерть станції), прогнози, злиття джерел, оцінка ємності.
- Ручна перевірка на станції власника перед кожним релізом.
